# 11. 거래 완료·공개 후기 — 통합 검토

2026-10-12 · 이슈 #19, curriculum 8단계

## 승인된 동작

구매자가 매칭된 요청을 완료한다. 완료된 채팅은 이전 대화를 읽을 수 있지만 새 메시지는 보내지 못한다. 구매자와 확정 판매자는 각각 평점 1~5와 본문 2~500자의 불변 후기를 한 건 작성한다. 사용자의 H4 변경 승인에 따라 후기는 작성 즉시 익명을 포함한 모두에게 요청 상세에서 공개된다. 작성 권한은 거래 당사자에게만 있다.

## 검증과 리뷰 판단

- 백엔드 전체 272개, 신규 기능 집중 30개 테스트 통과: [백엔드 검증](11-backend.md).
- 프론트엔드 최종 319개 테스트, lint, TypeScript 검사, Next.js build 통과: [프론트 검증](11-frontend.md).
- 공개 응답, 권한, Origin, 로그, 캐시, XSS, 데이터 보존 검토에서 차단할 보안 문제 없음: [보안 리뷰](11-security-review.md).
- 조회는 인덱스를 사용하는 단건/최대 2건 조회이며 완료·전송 잠금 순서가 직렬화를 보장한다: [성능 리뷰](11-performance-review.md).
- 성능 P-1은 수정 완료: 마이그레이션 첫 문장에 `SET LOCAL lock_timeout = '5s'`를 추가하고 오프라인 SQL 순서 검증 2개 테스트 통과. DB 재적용은 하지 않았다.
- 코디네이터가 확인한 SSR 경합은 수정 완료: 방 응답은 `matched`, 초기 메시지 응답은 `completed`인 경우에도 부모 화면을 정확히 한 번 갱신한다. 부모가 이미 `completed`이면 갱신하지 않는다. 회귀 테스트에서 기존 구현 실패와 수정 후 통과를 확인했다.
- P-2~P-4는 저위험 선택 최적화로 남긴다. 완료 직후 최대 한 번의 추가 화면 갱신, 기존 매칭과 같은 소유자 확인 전 행 잠금, 전송 쿼리의 추가 PK 조인이다. 기능 정확성과 이번 배포를 차단하지 않는다.

## 데이터와 배포

기존 Docker 로컬 DB를 사용했고 검증 데이터는 삭제하지 않았다. 로컬 revision은 `0007_completion_reviews`다. 새 환경 변수나 의존성은 없다. 서버 시작과 테스트는 운영 DB에 접근하지 않았다.

배포 순서는 마이그레이션 적용 후 프론트·백엔드 코드 배포다. `0007` downgrade는 DDL 전에 거부한다. 완료 데이터가 생긴 뒤에는 `completed`를 모르는 구버전 코드로 되돌릴 수 없으므로 수정 전진으로 대응한다. 이번 작업은 develop 대상 PR을 작성하며 운영 배포는 수행하지 않는다.

## 브라우저 검증

별도 UI 워커가 로컬 서버와 Orca 브라우저에서 필수 시나리오 1~7을 통과했다. 완료·양방향 후기 작성·비로그인/제3자/마감 판매자 공개 조회, 작성 권한 거절, 중복 처리, 판매자 폴링(2.7초/1.9초), 두 탭 완료, 375px 화면을 확인했다. 결과와 스크린샷 26장은 [UI 검증](11-ui.md)에 있다.

요청 상세의 모바일 폭도 보완했다. 명시적 한 열, `min-w-0`, 본문 줄바꿈을 적용하고 lint·타입 검사·기존 상세 테스트 7개 통과 후 UI 재측정에서 가로 넘침 0을 확인했다.

단일 브라우저 쿠키 저장소 때문에 상대 계정의 완료 트리거는 별도 HTTP 클라이언트로 실행했고, 일부 도구 클릭은 Orca eval의 DOM 클릭으로 보조했다. 모바일은 에뮬레이션이다. 이 한계는 테스트 목적을 충족하므로 수용한다. SSR 후기 조회 실패의 수동 재현은 제외했지만 해당 재조회·오류 UI는 단위 테스트로 확인했다. 기존 날짜 표기 차이와 대화가 없는 완료 방의 빈 메시지 문구는 비차단 경미 사항으로 기록했다.
