### 모바일 (375 × 812)

- 채팅방(완료·후기 카드): `scrollWidth 375`, 가로 overflow 0 (스샷 16a). 별점 5개·본문·시각이 줄바꿈되고 "공개된 후기 보기" 링크·완료 배너·비활성 입력이 가독 상태.
- 완료 확인 패널: 안내문 2줄 줄바꿈, "완료/취소" 버튼 나란히 표시(스샷 19). 매칭 전 화면은 스샷 18.
- 후기 폼: 별점 5개(탭 영역 약 44px), 본문 `0/500`, 공개 안내 박스(스샷 20·20b).
- 요청 상세 공개 후기 목록: 구매자/판매자 카드와 별점이 폭 안에 정상 표시(스샷 17, 익명 25).
- **발견 결함(기존 레이아웃, 패치됨)**: 패치 전 첫 측정에서 `/requests/09657042-…` 의 설명 본문이 카드 안에서 잘렸다("구매 요청입니다"의 "청입" 누락, 일부 요소 right=390 > 375). 원인은 `RequestDetail.tsx` 의 모바일 암시적 grid 열이 마스킹 이메일 min-content(≈349px)로 늘어난 것이다(초기 커밋부터 존재, step 8 diff와 무관). coordinator가 front에 전달해 `grid-cols-1` + `lg:grid-cols-[minmax(0,1fr)_280px]`, `min-w-0`, `break-words` 로 수정되었다. **패치 후 재측정: `innerWidth 375 = scrollWidth 375`, 본문 폭 293px, 잘림 없음, overflow 요소 0**(스샷 24). 데스크톱(lg)은 본문+구매자 aside 2열 유지(스샷 02). 이 결함의 첫 번째 clip 스샷은 패치 전 재촬영 과정에서 덮어써져 보존하지 못했다. 또한 제가 패치 적용 후 3회 측정한 값(overflow 0)을 근거로 한때 "재현 불가"라고 coordinator에 정정 보고했으나, 이는 패치 이후 측정이었으므로 잘못된 추론이었다(coordinator가 바로잡음).

## 콘솔·네트워크

검증에 쓴 두 페이지(page id 기준 누적 콘솔 버퍼 76건, 두 번째 탭 별도 확인)에서 `error` 로그 0건, hydration 경고 0건. `warning` 은 Next 15의 `scroll-behavior: smooth` 안내 1종(기존 레이아웃 속성, 이번 변경과 무관)뿐이다. 네트워크는 `POST /api/requests/*/complete`, `POST …/reviews` 가 예상 상태코드(200/201/409)였고 5xx 없음.

## 한계·관찰 (정직한 기록)

1. **단일 쿠키 저장소**: 인증 origin이 `http://localhost:3000` 하나뿐이고 Orca CLI에 새 프로필 생성 수단이 없어(`tab create --profile` 은 기존 id만 허용) 브라우저는 한 번에 한 계정으로만 로그인된다. 구매자·판매자 UI는 순차로 검증했고, 시나리오 3의 구매자 측 완료만 HTTP 클라이언트로 트리거했다.
2. **Orca `click` 불안정**: 헤더 "로그아웃", 로그인 "제출", 스크롤 직후 첫 클릭이 무반응일 때가 있었다(네트워크에 요청 없음). coordinator 안내대로 개발 서버 산출물 불일치로 인한 비-hydration 구간일 가능성이 있고, 이런 경우 DOM `click()`(eval)으로 같은 핸들러를 실행했다. 이 방식은 로그아웃·로그인 제출·두 탭 동시 완료·세 번 클릭 실험에만 썼고, 구매자 완료·후기 제출 등 주요 경로는 Orca `click` 으로도 확인했다.
3. **`fill` 은 `maxLength` 를 우회**한다(501자가 들어감). 500자 제한은 실제 키 입력(`keypress`)으로 확인했다.
4. **`full-screenshot` 은 sticky 헤더 때문에 화면 영역이 중복**되어 증거로 부적합해 모두 뷰포트 스크린샷으로 교체했다. 일부 스크린샷은 `scrollTo` 로 해당 영역을 화면에 맞췄다.
5. **날짜 표기 불일치(경미, 기존 `formatDateTime`)**: 서버 렌더 직후 snapshot에는 `PM 10:45`, 하이드레이션 후/클라이언트 렌더에는 `오후 10:45` 로 보인 구간이 있었다. 콘솔 hydration 경고는 없었다.
6. **문구 관찰(경미)**: 대화가 없는 완료 방에서도 "아직 메시지가 없어요. 첫 메시지를 보내 보세요."가 표시된다(입력은 비활성이라 안내와 어긋남).
7. 스펙 §13.5의 10번(SSR 후기 조회 실패 → "다시 시도")은 수동 재현이 어려워 대상에서 제외하고 정상 경로의 콘솔·hydration 오류 없음만 확인했다.
8. 모바일은 실기기가 아닌 Orca Chromium 에뮬레이션이다(iOS/Android 폰트·키보드·safe area 미포함).
9. 검증 중 `POST /api/auth/login` 429(RATE_LIMITED)를 한 번 만났다(HTTP 시드 스크립트의 반복 로그인). 대기 후 해소되었고 앱 결함이 아니다.

## 결론

필수 시나리오 1~7은 모두 통과했다. 소스 결함은 기존 RequestDetail 모바일 그리드 1건이며 패치 후 해소를 확인했고, 나머지 관찰(날짜 표기 불일치, 빈 메시지 안내 문구)은 비차단 경미 사항이다. 위 한계(단일 쿠키 저장소로 인한 HTTP 완료 트리거, Orca `click` 불안정으로 인한 DOM 클릭 보조, 모바일 에뮬레이션)는 coordinator가 판단해 수용 여부를 결정한다.
